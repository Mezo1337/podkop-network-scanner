# Podkop Network Scanner

Программа для Windows 10/11 (x64). Собирает домены и IP-адреса, которые **на самом деле** используют сайт или программа, проверяет их актуальность и готовит списки для полей Podkop «Список пользовательских доменов» и «Список пользовательских подсетей» на роутере OpenWrt.

Работает локально: без регистрации, без телеметрии, история хранится только на вашем компьютере.

---

## 1. Установка

1. Распакуйте `PodkopScanner-win-x64.zip` в любую папку, например `C:\Programs\PodkopScanner`.
2. Запустите `PodkopScanner.exe`. Устанавливать .NET не нужно: сборка самодостаточная.
3. Для анализа сайтов нужен браузер. Есть два варианта:
   * **Microsoft Edge** (уже есть в Windows): «Настройки и подключение» → «Браузер для анализа» → Microsoft Edge;
   * **встроенный Chromium**: кнопка «Установить Chromium» (около 170 МБ, загружается в `%LOCALAPPDATA%\ms-playwright`).
4. Для полного анализа программ и игр (UDP, DNS, SNI) нужны права администратора. Нажмите «Перезапустить от администратора» слева внизу. Драйвер WinDivert (`WinDivert64.sys`, подписан, лицензия LGPLv3) лежит рядом с exe. Он загружается только на время мониторинга и выгружается после остановки. Программа сама ничего не устанавливает в систему и не меняет настройки Windows.

Где хранятся данные: `%LOCALAPPDATA%\PodkopNetworkScanner` (база `podkop-scanner.db`, `settings.json`, журнал ошибок, резервные копии). Если положить рядом с exe пустой файл `portable.txt`, данные будут храниться в папке `data` рядом с программой.

> Антивирус может отметить WinDivert как «инструмент перехвата трафика». Отключать защиту **не нужно**. Если драйвер заблокирован, программа сообщит об этом и продолжит работу в ограниченном режиме (только TCP). Добавлять исключение или нет — решаете вы.

## 2. Как это вставляется в Podkop (проверено по исходникам Podkop, октябрь 2026)

| Поле Podkop | Что принимает | Как трактует |
|---|---|---|
| Список пользовательских доменов (`user_domains` / `user_domains_text`) | `example.com`, `sub.example.com`; в текстовом режиме — через запятую, пробел или перевод строки, комментарии `//` | правило sing-box **`domain_suffix`**: `example.com` охватывает **все** поддомены |
| Список пользовательских подсетей (`user_subnets` / `user_subnets_text`) | `X.X.X.X` или `X.X.X.X/Y`, **только IPv4**, не `0.0.0.0` | правило `ip_cidr` + набор nftables |
| Локальные списки (`local_domain_lists` / `local_subnet_lists`) | путь к файлу на роутере; одна запись на строку, **без комментариев** | то же |
| Удалённые списки (`remote_*_lists`) | ссылка; `.json` и `.srs` — наборы правил sing-box, любые другие — простой текст | то же |

Программа выводит строго одну запись на строку, без комментариев, дат и URL. IPv6 в поле подсетей не выводится, потому что валидатор Podkop его не принимает. При желании IPv6 можно добавить в JSON-набор правил sing-box.

**Вставка в LuCI:** Podkop → секция → «Тип списка пользовательских доменов» = *Text List* → вставьте. Аналогично для подсетей.

## 3. Сценарии

### A. Сайт
1. «+ Сайт» → название (или просто вставьте ссылку, проект создастся сам).
2. Вкладка «Анализ сайта» → вставьте ссылку → «Начать анализ».
3. Откроется настоящий браузер. Войдите в аккаунт, откройте видео, перейдите по разделам. Всё попадает в результаты в реальном времени.
4. «Остановить». Найденные домены будут проверены через DNS.
5. Вкладка «Экспорт в Podkop» → «Скопировать домены» / «Скопировать IP и подсети».

Что сохраняется: имя хоста, тип ресурса, IP соединения. **Не сохраняются** пароли, cookies, токены, содержимое страниц и сообщений, пути и параметры URL. Контекст браузера временный, как в режиме инкогнито.

### B. Программа или игра
1. «+ Программа» → «Выбрать EXE…» или «Выбрать запущенную программу…».
2. Включите «Запустить выбранный EXE после старта мониторинга» или запустите программу сами **после** нажатия «Начать мониторинг». Захват стартует раньше программы, чтобы не пропустить короткие соединения.
3. Пользуйтесь программой: лаунчер, вход, меню, матч, голосовой чат. Вкладка «Соединения (live)» показывает подключения в реальном времени.
4. «Остановить» → проверьте категории (авторизация, игровой сервер, голос и т.д.) → снимите лишние галочки → экспорт.

Как соединение привязывается к программе (только достоверные способы):
* **WinDivert FLOW**: каждый TCP/UDP-поток с PID процесса из ядра (WFP ALE);
* **WinDivert SOCKET**: каждый вызов `connect()`, включая неудачные;
* **TLS SNI**: имя сервера из ClientHello, привязанное к PID через точный 5-кортеж потока;
* **DNS процесса**: ETW `Microsoft-Windows-DNS-Client` и DNS-ответы на UDP-сокет процесса;
* **локальный прокси**: если программа работает через прокси-клиент на 127.0.0.1 (например, системный прокси Windows), её назначения берутся из запросов `CONNECT`/SOCKS к этому прокси;
* дочерние процессы учитываются по дереву процессов (с защитой от повторного использования PID). Процессы из папки программы учитываются только по отдельной галочке и отмечаются как «связанные».

Соединения общих служб Windows (svchost, System) показываются серым как **неопределённые** и в проект не сохраняются.

### C. Обновление старого проекта
Откройте проект → «⟳ Обновить адреса». Все домены будут разрешены повторно, и вы увидите отчёт: новые IP и IP, пропавшие из ответа. Ничего не удаляется автоматически. Статус «Не подтверждён повторной проверкой» ставится только после двух проверок подряд. Ping не используется. Перед изменениями сохраняется версия списка, во вкладке «История» есть сравнение и откат.

Автообновление: «Настройки» → «Актуализация» (пока программа открыта). Чтобы обновлять, когда программа закрыта, создайте сами задачу в Планировщике заданий: `PodkopScanner.exe --refresh-all`.

### D. Через свой прокси
«Настройки и подключение» → «B — через прокси» → SOCKS5 / HTTP / HTTPS, адрес, порт, логин и пароль (или ссылка `socks5://user:pass@host:port` → «Разобрать») → «Проверить маршрут и внешний IP» или «Сравнить: напрямую и через прокси». Затем в «Анализе сайта» выберите «Через прокси (из настроек)».
* Через прокси действительно идёт весь трафик браузера. Для SOCKS5 с логином используется локальный мост, потому что Chromium не умеет авторизацию SOCKS5.
* В этом режиме IP соединения браузера — это адрес прокси, поэтому он **не** записывается как IP сервера. IP серверов определяются DNS-проверкой. Для «DNS как видит прокси» выберите DoH или DNS по TCP: они идут через тот же маршрут.
* Перед анализом прокси проверяется. Если он не работает, анализ не запускается, чтобы прямое подключение не выдавалось за проксированное.
* Если в Windows включён системный прокси, режим «Напрямую» его **не** использует. Для анализа через системный прокси есть отдельный вариант «Системный прокси Windows».

Пароль прокси хранится зашифрованным средствами Windows (DPAPI, только для вашей учётной записи).

## 4. Достоверность и статусы

| Уровень | Когда |
|---|---|
| **Высокая** | замечено в контролируемом браузере или в потоке выбранного процесса (FLOW/connect/SNI/запрос к прокси); подтверждено вручную |
| **Средняя** | актуальный DNS-ответ; DNS-запрос процесса без последующего соединения; процесс из папки программы; официальный список; журнал роутера/прокси |
| **Низкая** | импорт; наблюдения старше 60 дней (срок настраивается) |

Это детерминированные правила, а не оценки «на глаз». Низкая достоверность **никогда** не включается в экспорт без вашего решения. По умолчанию включаются домены высокой достоверности, кроме рекламы, аналитики и баннеров cookie.

**Для проектов-сайтов** включаются только домены самого сайта (колонка «Чей домен»): тот же основной домен (`*.duolingo.com`), родственные домены с тем же названием (`duolingocdn.com`) и персональные CDN-поддомены, загруженные сайтом (`dxxxx.cloudfront.net`). Сторонние сервисы (вход через Google, reCAPTCHA, шрифты Google, OneTrust/Cookielaw и т.п.) показываются с пояснением, но **не отмечены**. Если без них что-то не работает, отметьте их сами или добавьте в белый список. Для программ включаются и IP высокой достоверности. Для сайтов IP по умолчанию не включаются: домена достаточно, а IP CDN меняются.

Статусы: «Подтверждён текущим соединением» · «Получен из актуального DNS-ответа» · «Подтверждён официальным источником» · «Ранее наблюдался» · «Не подтверждён повторной проверкой» · «Требует ручной проверки».

## 5. IP и подсети: что программа никогда не делает сама

* Не превращает IP в /24, /16 и т.п. Одиночный IP остаётся `/32`.
* «Точная агрегация» объединяет только смежные или вложенные сети. Ни один новый адрес при этом не добавляется (это проверено тестом).
* «Официальные диапазоны» (Cloudflare, Google, AWS, Fastly, Telegram, GitHub) только **помечают** IP. Подсети общих CDN и облаков не предлагаются. Подсети собственных сетей сервиса (Telegram, GitHub) предлагаются выключенными, решение за вами. Изменения официальных списков между проверками показываются отдельно.
* Перед включением сети шире /20 показывается предупреждение.
* «ASN» определяет оператора через DNS-сервис Team Cymru, только по нажатию и после подтверждения.

**Обобщённый режим** («Обобщение…») предлагает заменить поддомены родительским доменом. Условие: замечено не меньше трёх поддоменов. Предложение никогда не делается для общих платформ (amazonaws.com, cloudfront.net, googleusercontent.com и т.п.). Помните, что в Podkop запись `example.com` охватывает **все** поддомены. По умолчанию используется точный режим.

## 6. Импорт

Вкладка «Импорт списков»: вставка текста, файл (TXT/CSV/JSON/LST), прямая ссылка, GitHub (ссылки `blob` превращаются в `raw`), Gist, кнопка «Списки itdoginfo/allow-domains…». Распознаются форматы dnsmasq, clash, hosts, adblock, наборы правил sing-box (`.json`; `.srs` — при указанном `sing-box.exe`), вывод `tcpdump`/`tshark`, CSV PCAPdroid, журналы sing-box (галочка «Это журнал роутера/прокси»). Импортированные записи помечаются отдельно и получают низкую достоверность.

Советы по сбору на роутере и телефоне (по статье itdog.info): `tcpdump -i br-lan host <IP устройства> and port 53` на OpenWrt, PCAPdroid на Android. Результат можно вставить сюда.

## 7. Файлы экспорта

* `domains.txt`, `subnets.txt` — как в полях Podkop;
* «Локальные списки .lst…» — для `local_domain_lists`/`local_subnet_lists` (кладите в `/etc/podkop/`, а не в `/tmp`: `/tmp` очищается при перезагрузке);
* «Набор правил sing-box .json…» — `{"version":1,"rules":[{"domain_suffix":[…]}]}` и отдельно `ip_cidr`, для `remote_*_lists`;
* «Скомпилировать .srs…» — через официальную `sing-box rule-set compile` (укажите путь к `sing-box.exe`). Бинарный формат программа не подделывает;
* «Подробный JSON…» — все записи с источниками, датами и достоверностью;
* «Изменения с прошлой версии» — что добавилось и что убрано.

## 9. Ограничения (честно)

* **Никакой метод не гарантирует, что найдены все адреса.** Используйте все функции программы и повторяйте сканирование.
* **Без прав администратора** анализ программ видит только TCP (опрос таблицы соединений). UDP, DNS и SNI не видны, очень короткие соединения могут быть пропущены.
* **DNS-over-HTTPS внутри программы** (например, браузер с «безопасным DNS») не виден через ETW. Имя тогда берётся из TLS SNI, если оно доступно.
* **TLS ECH**: в SNI видно только внешнее имя фронта (например, Cloudflare). Такие записи отмечаются отдельно.
* **QUIC/HTTP3 в программах**: имя сервера внутри QUIC зашифровано. Сохраняется IP и UDP-поток, а домен — только из DNS процесса.
* **Подключение сразу по IP**: сохраняется IP с пометкой «имя сервера не установлено».
* **VPN/TUN с fake-ip (198.18.x.x)**: настоящие IP не видны. Программа это определяет и предупреждает. Домены (DNS/SNI) остаются достоверными.
* **Программы через прокси-клиент**: назначения видны, если клиент — локальный HTTP/SOCKS-прокси (при правах администратора). Через «чужой» VPN без локального прокси видны только адреса до туннеля, со стороны приложения.
* **Обычный SOCKS5 не умеет сам направлять трафик произвольного EXE.** Сканер только наблюдает и ничего не перенаправляет.
* **Службы Windows** (svchost и др.) не связываются с программой и показываются как неопределённые.
* **GeoDNS и CDN**: ответы DNS зависят от региона и маршрута. Сравнивайте «напрямую» и «через прокси».
* **WinDivert**: только x64. Может конфликтовать с другой версией WinDivert, уже загруженной другой программой (GoodbyeDPI, zapret). Программа покажет понятное сообщение.
* Классификация назначения (API, CDN, авторизация, голос…) — эвристическая подсказка, у неё всегда указан уровень уверенности и обоснование.

## 10. Сборка из исходников

```powershell
.\build.ps1                # модульные тесты + самодостаточная сборка в .\dist
.\build.ps1 -Integration   # плюс интеграционные тесты (сеть, Chromium)
```

Структура:

```
src/PodkopScanner.Core     — ядро (без интерфейса)
  Net/        домены (PSL, IDN), IP/CIDR, DNS (UDP/TCP/DoH/через прокси), прокси, мост SOCKS5, ASN, официальные диапазоны, системный прокси
  Web/        анализ сайтов (Playwright, Chromium/Edge)
  Monitoring/ WinDivert FLOW/SOCKET/NETWORK, ETW DNS, IP Helper, дерево процессов, SNI, запросы к прокси, самопроверка
  Analysis/   классификация, правила достоверности
  Data/       SQLite (WAL, проверка целостности, резервные копии), исключения, версии
  Export/     генератор списков Podkop, .lst/.json/.srs, сравнение версий, обобщение
  Import/     разбор списков и журналов, GitHub
  Update/     сессия сканирования, обновление адресов
src/PodkopScanner.App      — интерфейс WPF (тёмная тема, русский язык)
tests/PodkopScanner.Tests  — xUnit: модульные и интеграционные тесты
native/x64                 — WinDivert 2.2.2 (LGPLv3)
```
